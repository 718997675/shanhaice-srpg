## 0. 诊断：两个独立病灶

### 病灶一：张力被"透明"吃掉了

你为可读性与公平做得极多（战斗预测、全加成可见、引导、悔棋、公式透明）。这是身份，不能丢。但 **透明 + 可逆 = 安全，安全 = 没有那种感觉**。  
FE4 的感觉 = **不可逆的代价 × 史诗尺度 × 代际宿命**。你的不可逆只有"战死"，还被"替补 + 传承 + 悔棋"三重兜底。

### 病灶二：呈现层太"素"，大脑不认这是"一个世界"

- 战斗：有动作、有数字，但没有"顿"和"爆" → 打不动。
- 物品：**全靠文字**（"铁剑 / 庚金剑气 / 疗伤药"）→ 商店、行囊、预测界面像一张表格，没有"东西"的实感。
- 这两点共同指向：**信息传递方式太抽象**。玩家不是在"看世界"，是在"读数据"。

> 二期 = 给透明系统加**三层不可逆**（主轴一二三）＋ 给呈现层加**手感与物感**（主轴四）。

## 2. 主轴一~三 · 规格摘要

### A. 大地图战略层（P1）

- 新数据：`campaign.strategy = { front, deploy:{charId:'front'|'rear'|'reserve'}, lastOrder }`，`normalizeCampaign` 补默认值。
- 每章 `entryRules`：本战线者开局在场；另一战线者本章缺席（或第 N 回合增援）；替补默认 reserve。
- **缺席即压力**：分兵代价不是数字，是"这章少一个人"。
- 与心结打通：被分到未选路线 → 自动挂心结（把心结从叙事变成玩家自己分的兵）。
- 红线：不做建造/据点经营，只做"人往哪放"。

### B. 薪火授业（P2）

- 新数据：`campaign.sukui=[{mentor,pupil,skillId,ch}]`，受业者技能带 `source:'sukui:<mentor>'`。
- 每章 1 次，转 1 个**被动**（不可转个人技/传说技），不可逆，战斗/图鉴显示导师名。
- 与 4.5 殉志传承共用传递模型，触发从"死亡"扩到"主动传授"。
- 剧情绑定：外传「岩隈·故国」「墨鸦·旧影」通关解锁对应授业。

### C. 圣脉纯度（P3）

- `char.bloodline={tier:'none'|'minor'|'major'|'pure', school}`。
- minor +1 全属性；major +2 + 圣武器槽；pure +3 + 阵眼额外 +5 命中。全进 `modsFor`，预测可见。
- 纯度靠解锁对应血统的异闻录条目提升（知识→养成资源）。
- 红线：总增益 ≤ 传说武器 +25%；只加我方。

### D. 宿命脚本（P1，情绪密度最高）

- `campaign.fate={}` 存判定标记。
- 例：第 8 章开局判 `support(墨鸦,云策)`：< B 且存活 → 重逢戏挡刀**永久死亡**（英魂碑自动补遗言）；≥ B → 重伤（本章 HP 上限 -20%）存活。
- **必须可避免**：机制说明库 + 军议提示明写"关系决定命运"。
- 钩子：`SUPPORT_RANKS`(20/50/90)、英魂碑、替补。

### E. 军令 + 声望（P2）

- `campaign.renown`、`campaign.commandUsed`。
- 每章「军议」3 选 1：重补给（修耐久）/ 急行（移动+1，初始 HP-5%）/ 固守（首回合防+2）。
- 声望来源：路线、救援、心结了断；门槛解锁替补、影响多结局第三档。
- 红线：每章限 1，不做 micro-optimize。

### F. 机动观感（P2·低成本）

- `moveClass:'cavalry'|'flying'|'infantry'`；拖尾 + 更远可达高亮；
- 复用预测系统做「战前部署预览」：拖动看初始可达范围。

# 主轴四 · 呈现

## G. 打击感与必杀演出

### G.1 五个真凶

1. **没有顿帧**（90% 的锅）：击中瞬间画面不停，动作滑过去。
2. **没有预备动作**：上来就挥，无蓄力对比。
3. **闪白/抖动/击退缺一**：反馈不齐就"软"。
4. **线性运动**：`x+=v` 匀速像 PPT。
5. **必杀只是"伤害更大的同一招"**：结构没变，观感就没变。

> **打击感 = 80% 时间（帧）+ 20% 画面。** 粒子加再多，没顿帧就是棉花。

### G.2 帧预算（60fps）

**普通命中（30 帧 = 0.5s）**

| 阶段     | 帧     | 内容                   |
| ------ | ----- | -------------------- |
| 预备     | 6     | 后仰蓄力、武器微抬            |
| 突进     | 5     | easeOutCubic 前冲 + 拖影 |
| 命中     | 1     | 冲击白帧                 |
| **顿帧** | **4** | 全冻结 + 抖动峰值 + 粒子爆发    |
| 击退     | 8     | 后滑 + 挤压回弹 + 数字弹出     |
| 收势     | 6     | 归位、拖尾淡出              |

**必杀（58 帧 ≈ 1.0s）**

| 阶段     | 帧     | 内容                 |
| ------ | ----- | ------------------ |
| 预兆     | 10    | 镜头轻推 + 静音一拍 + 描边发光 |
| 立绘切入   | 8     | 「决意」表情立绘侧滑 + 斜切    |
| 蓄力慢放   | 8     | timeScale 0.35     |
| 冲击帧    | 2     | 黑白闪 + 大字「会心」       |
| **顿帧** | **8** | 冻结 + 强震 + 径向粒子     |
| 爆发     | 10    | 冲击波 + 大幅击退 + 数字放大  |
| 余韵     | 12    | 镜头拉回、慢速回正          |

**击杀**：+0.3s 去饱和 + 0.25× 慢动作 + 暗角脉冲 + 倒地。

### G.3 必杀四段式（结构，不是数值）

**静**（静音 1 拍 + 微推）→ **蓄**（立绘 cut-in，用已有「决意」表情）→ **爆**（黑白冲击帧 → 8 帧顿帧 → 强震 + 径向粒子）→ **余**（慢动作回正 + 数字停留 + 硬直）。  
核心技术：**"静默一拍 → 重击"**，靠落差制造爽感。

### G.7 与现有规范整合

- ≤4s：普通 0.5s / 必杀 1.0s / 击杀 +0.3s，一段"攻击+反击+追击"约 3 段仍在 4s 内。
- 关闭动画：直接跳结算，Juice 全部随动画层跳过。
- ×2 倍速：**顿帧与 slow 按比例缩短**，否则显拖沓。
- 点击跳过：**必须清零 `hitstop/timeScale/flash`**，否则卡半帧。
- 无障碍：加「减少动态效果」开关，关抖动/闪白/慢动作，只留 2 帧顿帧。
- 你是**先算后回放**的回合制，顿帧只冻结回放时钟，绝不碰逻辑——最安全。

### G.8 调参表

| 参数     | 轻击  | 重击  | 必杀        | 击杀       |
| ------ | --- | --- | --------- | -------- |
| 顿帧     | 3   | 5   | 8         | 12 帧     |
| 闪白     | .18 | .30 | .70       | .80      |
| trauma | .12 | .30 | .60       | .75      |
| 击退 px  | 8   | 16  | 26        | 34       |
| 粒子     | 8   | 16  | 26        | 34       |
| 慢动作    | —   | —   | .35×/.18s | .25×/.4s |

**音效（无素材方案）**：WebAudio 现场合成——低频 sine thump（90→30Hz 下滑）+ 噪声 crunch（`Math.random` 衰减缓冲）。必杀前**先静音 0.1s** 再放，落差即爽感。零素材成本，风格统一。

**触觉**：`navigator.vibrate([10])` / 必杀 `[0,28,18,55]` / 击杀 `[0,18,18,18,18,90]`。安卓有效，iOS 网页无效——别指望。

**配套**（可直接搬）：抖动渲染层、挤压回弹 `scale(1+sq*0.35, 1-sq*0.28)`、冲击帧 2 帧白底+粗黑斜切、粒子对象池（`globalCompositeOperation='lighter'`、重力）、伤害数字 `easeOutBack` 弹出、击杀去饱和（**预渲染灰度版**，别用 `ctx.filter`，安卓 WebView 会卡）。

## H. 物品图标化（武器 / 灵术 / 药水 / 材料）

### H.1 为什么必须做

文字传递的是"参数"，图标传递的是"东西"。

- **识别速度**：图标比文字快约 3~5 倍（商店扫读、行囊找药时体感差异极大）。
- **代入感**：玩家记得"那把红穗的刀"，不记得"攻击 14 耐久 40"。
- **收藏欲**：图标是图鉴与传说武器的"实体感"来源，直接影响二周目动力。
- **UI 密度**：图标+名+关键数值，比长文字行更省屏（844×390 横屏尤其紧）。

### H.2 图标分类与数量（约 79 枚）

| 类别      | 明细                                    | 数量      | 生产方式           |
| ------- | ------------------------------------- | ------- | -------------- |
| 基础武器    | 10 类（剑/重刃/枪/弓/匕首/符/杖/兽爪/骨笛/潮声）× 铁/钢/银 | 30      | **同形换材质色**（模板） |
| 专属武器    | 14 人各 1 把                             | 14      | 基础形 + 角色标志物    |
| 传说武器    | 10 把                                  | 10      | 独立作画（带光效）      |
| 灵术      | 五行 ×（单体 + 范围）= 10                     | 10      | 五行符号模板         |
| 药水 / 道具 | 疗伤 / 解毒 / 复活类 / 传送类 / 增益 等            | 8       | 瓶型模板           |
| 材料 / 脉印 | 铁髓 / 钢核 / 银晶 / 脉印                     | 4       | 独立小图           |
| 神兽契约    | 白泽 / 毕方 / 穷奇                          | 3       | 独立             |
| **合计**  |                                       | **≈79** |                |

### H.3 视觉规范（守水墨风 + 小屏可辨）

**共同**：源图 192×192 PNG 透明底；显示 48~64px（商店/行囊），列表角标 32px。统一光源**左上**、墨线 3~4px、统一**圆角方底框**。武器 **45° 斜置**（刃朝右上）；瓶类**正立**；材料**等距块状**。**剪影优先**：只看黑白轮廓能认出是什么。色板沿用全游戏 ≤16 色，每类一个主色。

**稀有度底框**（描边 + 角饰，不额外加色）：普通=墨 `#2b2b2b`｜精良=青 `#2e7d7a`｜稀有=金 `#c9a227`｜传说=赤 `#a02c2c`（角饰加云纹）。

**类别形状编码**（形状优先于颜色）：剑=直刃+十字护手｜重刃=宽厚单刃+无护手｜枪=长杆+三角枪头（斜置）｜弓=弧形弓臂+弦｜匕首=短刃+短柄｜符=竖长符纸+朱砂笔迹｜杖=长杖+杖头｜兽爪=三钩爪形｜骨笛=短笛+骨节纹｜潮声=贝壳+波纹。

**五行灵术**：五色 + 独立符号：金=刃芒、木=藤蔓、水=水滴、火=焰舌、土=岩块。**单体** = 单符号居中；**范围** = 符号 + 范围框缩略（十字 5 / 方块 9 / 直线 3），一眼区分射程形状。

**药水 / 材料**：药水=圆瓶（回复）/ 方瓶（增益）/ 皮袋（杂项），液色区分类别（红=疗伤、绿=解毒、蓝=增益）。材料=矿物块 ×3 色 + 脉印（玉质符印）。

### H.4 模板化生产（控成本关键）

1. **铁/钢/银 = 同一底形换材质**：铁（哑光深灰）/ 钢（冷亮中灰 + 高光）/ 银（浅亮 + 冷调）。**1 套形 × 3 色**，30 枚实际只画 10 个形。
2. **专属武器 = 基础形 + 1 件角色标志物**（云策断剑缺口、墨鸦半截面具纹、虞素秋鲛绡穗）。不改整体轮廓，只加"记号"。
3. **传说武器 = 唯一需要独立作画**，并统一加"光效层"（外发光 + 粒子点）。
4. **灵术 = 1 个五行符号模板 × 单/范围两种框**，共 10 枚但只设计 5 个符号。
5. **药水 = 3 种瓶型 × 换液色**，8 枚约 3 个形。

> 结论：79 枚里真正"独立作画"的只有 **传说 10 + 契约 3 + 专属 14 ≈ 27 枚**，其余 52 枚靠模板，工作量可控。

### H.6 命名与接入

```
assets/icons/
  icon_item_<id>.png      基础/专属/传说武器
  icon_spell_<id>.png     灵术
  icon_use_<id>.png       药水 / 道具
```

接入点：商店/行囊/预测/强化/图鉴统一走 `itemIcon(id)`，从 manifest 取，缺图回退到**类别占位图标**（不要回退成文字，否则又回到"素"）。与单位图标共用同一套 `icon_` 前缀与规格。

### H.8 验收清单

1. **390px 屏、48px 下**：同类不同物品（铁剑 vs 钢剑 vs 银剑）能辨差异。
2. **黑白剪影测试**：只看轮廓能认出类别（剑/瓶/矿块）。
3. **色盲模拟**：不依赖红绿区分（药水靠瓶型、五行靠符号）。
4. **不冗余**：图标 + 名称并存，图标不替代可读文字（无障碍）。
5. **一致性**：79 枚摆一屏，光源、墨线、底框、视角不打架。
6. **缺图不露馅**：任何未交付物品显示类别占位图，永远不显示纯文字。

## 4. 本周就能做的 5 个微改动（几乎零成本）

## 5. 红线 & 不要做

- 不丢透明（预测/公式可见是身份）；重量来自"不可逆"，不来自"藏信息"。
- 不做据点经营、不做抽卡联网、不做子代。
- 永久死亡不被架空：薪火每章限 1、圣脉不加 AI、宿命脚本可避免。
- **别用图标替代文字**：图标 + 名称并存，图标是加速识别，不是取消可读性。
- **别再堆第 5 个系统**：二期只做 4 根主轴，每个模块都要能回答"哪一刻心动/哪一刻觉得像个世界"。

## 6. 怎么判断"回来了"（可测）

- 玩家能说出 **≥3 个"我后悔/我失去"的瞬间**？（宿命/传承）
- 盲测三问：哪一下最重？能感到"打中的那一下"吗？必杀是"同一招变强"还是"另一个东西"？
- 玩家是否**用图标指代物品**（"那把红穗的刀"）而非背数值？
- 试玩一句话反馈：是"系统好多/全是字"，还是"我把谁弄丢了/这道具真好看"？后者 = 成功。
