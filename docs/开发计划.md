### 1.2 决策：在基线上增量开发

1. **内核不用重写**：公式、RNG、寻路、AI、悔棋框架与 v2.7 完全同源；推倒重来 = 扔掉已调平的 26 武器 / 12 敌型 / 8 章地图 / 6 组支援对话，并重新验证数千行逻辑。
2. **v2.7 的新系统大多是"挂点"而非"重写"**：阵眼升阶 = 节点加一个 `tier` 字段；改造地形 = 地形动态层（悔棋快照已含动态层的设计直接落地）；分支路线 = 章节图加 A/B 路由；殉志传承 = 挂在已存在的 `death` 事件上；多结局 = 结算条件判断；五行法术/传送/强化 = data 加表 + battle 加消耗逻辑。
3. **工程红线基线已满足**：零依赖、多 script 标签命名空间、file:// 可跑、数据驱动——新计划只需延续同一风格。
4. **风险可控**：battle.js 单文件 2211 行偏大，新系统一律放新文件（js/systems/*.js），按序加载，避免其继续膨胀。

## 3. 关键数据 Schema 增量（先定稿，开发即填表）

**五行法术**（data-systems.js 每条）：

```
{ id, name, element(金木水火土), kind(single/aoe), rng:[1,2]|cross5|square9,
  mt, hit, uses(次数,0消失), price, desc, bossDrop?, effectiveTags? }
// 相克：金→木→土→水→火→金，对目标 element 差 ±15 命中 ±2 伤害（复用 TRIANGLE 同形结构）
```

**阵眼升阶/改造**（nodes2.js 扩展 battle 现有 nodes）：

```
{ id, x, y, type(attack/life/flow/guard),
  tier:0|1|2,            // 连续驻守 2 回合 +1，效果翻倍
  transform?:{ flow→修断桥, life→净化毒沼, guard→生成掩体 },
  resonance?:true }      // 第 8/9 章：3 座全控触发事件
```

**地形动态层**（悔棋快照扩展，battle.js 快照已含 nodes，补 terrainDyn）：

```
terrainDyn: { "x,y": { kind:'ice'|'swamp'|'cover'|'bridge', state } }
```

**存档**：现 SAVE_VERSION=3，任何结构变更先 +1 并写迁移（现成规则，延续）。

**manifest.json 已建好**（工作区 assets/）：立绘/图标交付登记处；基础版本 assets/portraits/*.svg 为程序化占位，豆包 PNG 到位后在 manifest 登记并切换加载路径。

## 6. 风险与对策

| 风险                    | 对策                                         |
| --------------------- | ------------------------------------------ |
| battle.js 单文件过大，新系统难插 | 新系统一律独立文件 + script 按序加载；只以事件/钩子与 battle 交互 |

| 分支路线内容量翻倍             | A/B 共用结局与尾声，差异集中在 6 个路线章节 + 心结对话           |
